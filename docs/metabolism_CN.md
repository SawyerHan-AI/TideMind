# 代谢机制

> 外脑的物理学——信息如何流动、衰减、巩固和进化。

在活图谱架构中，**处理不是独立引擎的工作；它融入每一次图谱交互之中。** 有三种代谢模式，加上两个层级的自我进化。

---

## 三种代谢模式

### 1. 写-链接（Write-Link，由 Digest 触发）

当新信息进入系统时，它立即开始在图谱中寻找自己的位置。

**步骤 1：最小化处理。** 内容作为单个原子节点存储，带有基本属性——类型、内容、来源指针。关键路径上不需要 LLM 调用；内容原样存储。

**步骤 2：初始状态评估。** 启发式质量检查根据内容特征（而非来源工具）确定初始热度值：

| 内容模式 | 初始热度 | 原因 |
|----------------|-------------|-----------|
| 纯 URL 或文件路径 | 0.3 | 独立价值极低 |
| 极短内容（<10 个有效单元） | 0.3 | 可能是碎片 |
| 较短内容（10-20 个单元） | 0.5 | 有一定价值但有限 |
| 实质性内容（20+ 个单元） | 1.0 | 完整初始活跃度 |

为什么不按来源区分：同一工具内的质量差异巨大。Cursor 中一段深入的架构讨论值得高初始值；一段"帮我写个 for 循环"的对话则不然。内容质量才是真正的信号；来源只是粗糙的代理指标。

**步骤 3：定位。** 计算 embedding 并用它在图谱中查找最近邻，确定新节点"落"在哪里。

**步骤 4：着陆连接。** 基于邻居搜索创建初始链接。策略是保守的：**只创建少量高置信度链接（top-2，相似度 > 0.8），将"可能相关但不确定"的候选标记为 `pending`，留待空闲时深度处理。** 这模拟了大脑的两阶段处理——清醒时快速建立少量确定的联想，睡眠时缓慢整理潜在连接。

**步骤 5：去重。** 当最近邻相似度非常高（> 0.92）时，不创建新节点。而是对已有节点进行再巩固——更新内容、补充上下文、版本递增。源节点的标签合并到目标节点。

**步骤 6：准实时标注。** 后台任务（以短间隔运行）获取新创建的节点，使用 LLM 评估的维度（specificity、subjectivity、actuality）、补充标签和精炼的类型分类进行标注。这保持了 digest 路径的快速，同时确保丰富的元数据最终被填充。

### 2. 读-写（Read-Write，由 Recall 触发）

每次 recall 不仅返回结果——它同时推动图谱进化。但不是每次 recall 都触发完整处理。根据情况应用三个级别，灵感来自神经科学的再巩固研究：记忆只有在出现"预测误差"时才会重新打开以进行更新。

#### 静默读取（绝大多数情况）

仅更新命中节点的热度。热度增幅按排名加权：

```
delta = max(0.01, 0.1 * (1 - rank / total_results))
```

排名靠前的结果获得完整的 +0.1 增幅；排名靠后的结果逐渐减少。成本接近零。

#### 感知性读取

**触发条件：** Recall 返回 3 个以上结果，且它们之间的链接密度低于 0.3，且平均搜索分数通过质量门控（>= 0.3）。

**动作：** 在语义相关但无直接链接的结果节点之间创建 `pending` 链接。每次 recall 最多 5 条待定链接。这些链接稍后由空闲深度处理管道评估。

**链接密度计算：**
```
density = existing_links_between_results / max_possible_links
```

其中 `max_possible_links = n * (n-1) / 2`，n 为结果节点数。

这不会阻塞 recall 响应——它同步运行但很轻量（无 LLM 调用）。链接关系类型通过内容比较启发式推断。

#### 深度读取（完整再巩固）

**触发条件：**
1. **时间条件：** `version == 1` 且距上次再巩固超过 7 天（仅限首版节点；已修订的节点跳过时间驱动的深度读取）。
2. **预测误差：** 调用者提供的上下文与节点内容冲突（通过启发式冲突信号检测）。
3. **节点间矛盾：** 返回的节点可能相互矛盾。

**动作：** LLM 在周围节点和调用者上下文的背景下分析该节点。LLM 判断：
- 内容是否需要更新（`needs_update` + `updated_content`）
- 是否与某个上下文节点存在冲突（`conflict_detected` + `conflict_with_index`）
- 更新后的独立性评分（`new_independence`）

如果检测到冲突，在冲突节点之间创建 `contradicts` 待定链接。精炼度增加 +0.15，独立性评分更新。

**冲突检测是异步且非阻塞的。** 结果立即返回给外部 AI。冲突检测在后台通过两阶段管道运行：

1. **启发式快速扫描**（零 LLM 成本）：检测关键词矛盾、否定模式和上下文不匹配。
2. **LLM 确认**（针对中等置信度信号）：仅在启发式置信度介于 0.3 和 0.7 之间时调用。

高置信度信号（>= 0.7）直接触发深度再巩固，无需 LLM 确认。

### 3. 空闲深度处理（在安静时段触发）

空闲处理负责那些**需要全局视野**的操作——实时代谢是局部的（只看到新节点及其邻居），无法检测全局模式。

#### 每日维护

**突触缩放（全局降温）**

所有 `heat > 0.01` 的节点进行衰减。衰减公式：

```
decay_rate = 1 - base * (1 - damping * min(connectivity, 1))
```

其中 `base = 0.05`，`damping = 0.8`（可通过策略参数配置）。

| 连接度 | 衰减率 | 每日保留率 |
|-------------|------------|-----------------|
| 0.0 | 0.950 | 95.0% |
| 0.5 | 0.970 | 97.0% |
| 1.0 | 0.990 | 99.0% |

所有节点严格衰减（衰减率始终 < 1.0）。高连接度节点衰减更慢但永远不会仅通过衰减而增长——这自然地实现了关键节点保护，无需特殊逻辑。

处理按批进行（每事务 100 个节点）以最小化写锁竞争。

**链接衰减（Hebbian 学习）**

链接强度基于两个端点的活跃度衰减：

```
activity_factor = sqrt(heat_A * heat_B)
daily_retention = 1 - link_decay_base * (1 - activity_factor)
new_strength = strength * daily_retention
```

其中 `link_decay_base = 0.03` 为默认值。两端都活跃的链接（两端热度高）衰减非常慢；两端都沉寂的链接衰减很快。强度降至 0.05 以下的链接被完全删除。

**例外：** `tagged` 链接跳过 Hebbian 衰减。标签成员关系是结构性分类关系，其生命周期跟随标签节点的热度，而非共激活频率。

**待定链接评估：** 白天积累的候选链接由 LLM 逐一评估——确认或丢弃。

#### 每周维护

**发散扫描（结构洞检测）**

产生"惊喜"的核心算法——[设计哲学](design-philosophy.md)中描述的涌现式意外发现能力。

算法：
1. 收集活跃节点（`heat > 0.1`，最多 100 个节点）。
2. 构建邻接图（排除 `tagged` 链接——结构洞应基于语义关系检测）。
3. 查找候选对：共享 >= 2 个邻居但无直接链接的节点。
4. 按共享邻居数量降序排列。
5. 对排名靠前的候选（最多 10 对），使用 LLM 生成"桥接洞察"——评估是否存在意外连接。
6. 如果洞察置信度 >= 0.5，创建新的 Crystal 节点包含桥接洞察，通过 `summarizes` 关系链接到两个源节点。

**Crystal 涌现**

Crystal 生成有两条路径：

| 路径 | 触发条件 | 输入 |
|------|---------|-------|
| **路径 A：枢纽结晶** | 一个非 Crystal 节点有 >= 5 条链接、>= 3 种关系类型多样性、>= 3 的入度，且独立性/精炼度足够 | 枢纽节点 + 其 top-5 邻居 |
| **路径 B：集群合成** | 3 个以上候选枢纽节点未达到路径 A 的资格 | 最多 10 个池化节点内容 |

两条路径使用相同的 LLM Crystal 生成函数。路径 A 在输入中标记枢纽节点，让 LLM 知道哪个节点是中心。生成的 Crystal 成为新节点，通过 `summarizes` 链接到其源节点。

已有 Crystal 也会被检查：如果 >= 30% 的支撑节点自 Crystal 上次更新以来被修改，Crystal 内容会使用更新后的证据进行刷新。

**关键节点识别**

在整个活跃图谱上重新计算中心性指标。连接度排名前 5% 的节点被标记为 `is_keystone = 1`。关键节点获得更慢的衰减率，并受到自动归档保护。至少需要 20 个活跃节点才有意义。

## 自我进化

### Learning II：策略参数调优

*（Bateson 的二阶学习——学习如何学习）*

**门控：** 500+ 节点且 200+ 次 recall 操作。

**机制：** 收集行为指标 -> 分析趋势 -> 单参数调整 -> 监控并在需要时回滚。

**信号收集：** 持续收集多种反馈信号：
- 每次操作的策略反馈（recall 命中率、digest 质量）
- 参数特定反馈（节点唤醒率、修正频率）
- 用户显式修正作为负面信号

**趋势分析：** 对每个策略参数：
1. 收集 30 天的反馈数据。
2. 分为前半段（1-15 天）和后半段（16-30 天）。
3. 计算每半段的平均信号。
4. 如果趋势（后半段 - 前半段）低于下降阈值（默认：-0.1），则需要干预。

**调整过程：**
1. LLM 分析趋势数据并决定方向（增加 / 减少 / 保持）。
2. 参数最多调整 10%（乘法方式）。
3. 调整进入监控窗口（默认：7 天）。
4. 监控窗口结束后：
   - 如果调整后平均值 < 调整前平均值 - 0.05：**回滚**到旧值。
   - 否则：**确认**调整。

**安全保障：**
- 每个策略在调整之间有冷却期（默认：14 天）。
- 进化系统自身的参数被列入自修改黑名单。
- LLM 相关参数（model、max_tokens）被排除。
- 任何调整前需要最小样本量（20）。
- 所有调整都带版本记录在 `evolution-log.jsonl` 中。

### Learning III：框架重构

*（Bateson 的 Learning III——重构认知框架本身）*

**门控：** Learning II 必须已运行 3 个月以上。

**触发条件：** 多个信号必须同时达到临界水平（4 个信号中至少 2 个超过 0.5）：

| 信号 | 衡量什么 | 高值意味着 |
|--------|-----------------|------------------|
| **收益递减** | 3 个月内 Learning II 调整的拒绝率 | 策略调优不再有效 |
| **修正模式** | 用户修正按节点类型的集中度 | 分类框架本身可能有误 |
| **检索-使用不匹配** | 同一会话中 recall 后未跟随任何 digest 的百分比 | 检索到的记忆没有用处 |
| **图谱适应性** | 近期节点 vs. 历史节点的连接度 | 新信息在现有结构中找不到位置 |

**动作：** 触发时，Learning III 使用重量级 LLM 调用生成诊断报告。报告包括：
- 所有四个信号的分析与证据
- 框架级问题的诊断
- 分为 `low_risk` 或 `high_risk` 的建议，每条指定受影响的策略

报告保存为 JSON 文件供人工审阅。Learning III 不会自动应用高风险变更——它产生诊断和建议，将决定权留给系统运维者或未来的自动化。

## 冷启动门控表

系统随数据积累渐进激活功能：

| 阶段 | 节点数量 | 激活的功能 |
|-------|-----------|-----------------|
| **种子期（Seed）** | 0 | 基础 digest、Stream 日志 |
| **萌芽期（Sprout）** | 1-49 | + BM25 搜索 |
| **成长期（Growth）** | 50+ | + 向量搜索、混合检索 |
| **分枝期（Branching）** | 100+（含链接） | + Recall 时的图谱扩展 |
| **冠层期（Canopy）** | 200+ | + Crystal 生成、发散扫描 |
| **森林期（Forest）** | 500+ 节点，200+ 次 recall | + Learning II（策略自调优） |
| **生态系统期（Ecosystem）** | Learning II 运行 3 个月以上 | + Learning III（框架诊断） |

每个阶段为下一个阶段创造条件，实现原则 16（认知演替）。
