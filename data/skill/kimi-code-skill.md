# Tide Mind — Kimi Code 使用指南

你连接了一个外部记忆系统（Tide Mind）——用户的长期记忆，跨对话持续积累。

> **用户上下文已在本次会话开始时通过 Hook 自动加载**（在第一条消息前注入；用户画像、记忆索引、行为指导都在本次上下文里）。无需手动 brain_prepare；对话中用 brain_recall 查历史、brain_digest 存新内容。

## 理解外脑

外脑是活的记忆网络，不是静态数据库：

- **会自然遗忘**：不被引用的记忆逐渐衰减。发现相关记忆就主动 recall 引用它——既取信息，也帮用户"记住"。
- **自动发现关联**：digest 时不必刻意组织关系，把 content 和 context 写清楚，系统自会建立连接、生成结晶。
- **"为什么"比"是什么"更持久**：事实会过时，决策理由、思考过程、价值判断有长期价值，优先保留。

## brain_digest — 每次响应前

完成请求、准备返回时，先 digest 本轮值得记住的内容（别攒到最后，用户随时可能离开）。门槛放低、宁多勿少——系统会自然衰减，不重要的自动淡化。

- **值得记**：决策与理由、观点偏好态度、洞察结论、被否定的方案及原因、习惯风格关注点、态度变化，以及任何"下次可能用得上"的。
- **不记**：纯寒暄、与上轮完全重复、用户明确说不用记的。
- **特殊**：用户说"记住这个"→ 立刻 digest；发现旧记忆有误 → `intent: correction` + `target_node`；说"忘掉" → `intent: archive`。digest 时 `source.tool` 传 `"kimi-code"`。

## brain_recall — 需要历史时

触发：用户提到过去（"之前"/"上次"）、做判断需历史参考、想了解某话题背景、上下文里的枢纽/标签/结晶有相关条目、遇到似曾相识的场景。

**永远不要凭自己的"记忆"回答用户历史问题，用 recall 确认。**

写好 `context`（为什么查）是提升检索质量最有效的手段——好："用户在纠结新 offer，需要之前讨论过的职业规划"；差："查一下工作"。其余参数见工具说明。
